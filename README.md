# LR8 — Code Security Analysis

## Опис проєкту

Навчальний консольний застосунок Secure Records Manager
на мові C для демонстрації статичного та динамічного
аналізу безпеки програмного коду.

Програма підтримує перегляд, додавання, пошук і видалення
тестових записів в оперативній пам'яті.

Початкова версія містить навмисно закладені навчальні
недоліки. Вона призначена виключно для локального аналізу.

## Середовище

- Kali Linux 2026.3
- GCC 16.2.0
- GNU Make 4.4.1
- Cppcheck 2.22.0
- Valgrind 3.27.1
- AddressSanitizer
- Git 2.53.0

## Компіляція та запуск

    make
    ./build/records list
    ./build/records add Keyboard
    ./build/records search Laptop
    ./build/records delete Monitor

## Методи аналізу

Статичний аналіз:

- Cppcheck: warning, style, performance, portability,
  inconclusive.
- GCC Static Analyzer: -Wall -Wextra -fanalyzer.

Динамічний аналіз:

- Valgrind Memcheck з повною перевіркою витоків.
- AddressSanitizer та LeakSanitizer.

Повторна перевірка:

    bash scripts/run_sast.sh after
    bash scripts/run_dynamic.sh after

## Реєстр вразливостей

| ID | Проблема | CWE | Критичність | Статус |
|---|---|---|---|---|
| V-01 | Stack-buffer-overflow | CWE-787 | High | Fixed |
| V-02 | Use-after-free | CWE-416 | Medium | Fixed |
| V-03 | Memory leak | CWE-401 | Low | Fixed |

Критичність визначено експертно з урахуванням
локального характеру застосунку.

### V-01. Переповнення буфера

Причина: відсутність перевірки довжини вхідного рядка.
Наслідки: пошкодження пам'яті та аварійне завершення.
Виправлення: контроль довжини перед копіюванням.
Підтверджено AddressSanitizer.

### V-02. Use-after-free

Причина: звернення до пам'яті після її звільнення.
Наслідки: некоректна поведінка та порушення
цілісності даних.
Виправлення: зміна порядку операцій із пам'яттю.
Підтверджено GCC, Valgrind та AddressSanitizer.

### V-03. Витік пам'яті

Причина: відсутність звільнення тимчасового буфера.
Наслідки: неефективне використання ресурсів.
Виправлення: звільнення виділеної пам'яті.
Підтверджено GCC, Valgrind та LeakSanitizer.

характер і не є підтвердженою вразливістю.

## Артефакти

- src/ — вихідний код.
- scripts/ — автоматизовані перевірки.
- reports/before/ — початкові журнали.
- reports/after/ — кінцеві журнали.
- Makefile — конфігурація компіляції.

## Версії

- v1.0-baseline — початковий код.
- v2.0-fixed — виправлений код.

## Рекомендації

- Перевіряти довжину вхідних даних.
- Контролювати життєвий цикл виділеної пам'яті.
- Регулярно запускати статичні аналізатори.
- Виконувати позитивні, негативні та граничні тести.
- Повторювати перевірки після кожного виправлення.

## Висновок

Поєднання статичного та динамічного аналізу дозволило
виявити три унікальні вразливості та підтвердити
ефективність їх усунення. Повторні динамічні перевірки
не виявили помилок у досліджених сценаріях.

Отримані результати не гарантують абсолютної
відсутності інших вразливостей у програмі.
